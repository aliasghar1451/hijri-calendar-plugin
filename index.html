Plugin Demo

Hijri + Gregorian Calendar

Click any field below. A calendar opens with a toggle between Gregorian and Hijri. Pick a date in either calendar — the form always submits the canonical Gregorian YYYY-MM-DD.

Dependencies & load order

The plugin is standalone ES5 — no jQuery, no date library, no polyfills for IE11+. Only the stylesheet is a hard requirement. jQuery validate is needed only if you use gregorianValue on validated, model-bound fields.

FileNeeded?Version
hijri-calendar-plugin.css required ships with the plugin — keep the pair in sync
hijri-calendar-plugin.js required no dependencies
hijri-calendar-miqaats.js optional load after the plugin; no version coupling
jquery.js validation only 1.7+ — any 1.x / 2.x / 3.x
jquery.validate.js validation only 1.9+ (1.19 / 1.20 tested)
jquery.validate.unobtrusive.js validation only 3.2.x or 4.0.x 
<link rel="stylesheet" href="src/hijri-calendar/hijri-calendar-plugin.css">

<!-- validation stack first, if you use it -->
<script src="jquery.min.js"></script>
<script src="jquery.validate.min.js"></script>
<script src="jquery.validate.unobtrusive.min.js"></script>

<script src="hijri-calendar-plugin.js"></script>
<script src="hijri-calendar-miqaats.js"></script>   <!-- optional -->

Loading the plugin before the validation stack still works — it re-parses the form once the pickers are attached — but the order above avoids the double parse. If Bootstrap is in play, put the plugin's CSS after it so .hcp-input wins. With no jQuery validate on the page the plugin enforces required itself at submit time. Not required anywhere: Bootstrap, moment/dayjs, or a particular ASP.NET version.

gregorianValue — drop-in replacement mode

Normally the visible input submits its display text and the Gregorian date arrives as <name>_gregorian. With gregorianValue on, the input's own name submits YYYY-MM-DD as well — so you can swap this plugin into an existing app without changing any server code. The _gregorian field is still sent, for compatibility.

gv_off = display text
gv_on = YYYY-MM-DD
gv_optout = display text, even though a global default is set

ASP.NET MVC — asp-for + jQuery unobtrusive validation

gregorianValue moves the field's name onto a hidden sibling, and jQuery validate keys every rule off name. So the plugin moves asp-for's data-val-* attributes across with it: validation runs against the canonical YYYY-MM-DD value (not the display string, which no date rule could parse), the hidden field is tagged .hcp-validated so ignore: ":hidden" stops skipping it, and the error/valid classes are mirrored back onto the visible box. Your data-valmsg-for span needs no change. Submit this empty, then pick a date — the error clears.

Native required can't fire on a readonly input, so the plugin promotes it to data-val-required on the hidden field.
// Submit to see validation run.
@* Razor — nothing unusual, just add the two attributes *@
<input asp-for="Trip.Departure" data-hijri-picker data-gregorian-value />
<span asp-validation-for="Trip.Departure"></span>

@* Whole app at once, before the pickers attach: *@
<script>HijriCalendar.setDefaults({ gregorianValue: true });</script>

// Injected a validated date field later (partial view / AJAX modal)?
// Attach the picker first, then re-wire:
HijriCalendar.attach(input, { gregorianValue: true });
HijriCalendar.wireUnobtrusive();

Model binding is unaffected — Trip.Departure posts 2026-05-06, which DateTime binds natively. wireUnobtrusive() is called for you on load; it is a no-op when jQuery validate isn't on the page.

Miqaat markers

Load the optional hijri-calendar-miqaats.js and days carrying an occasion get a marker: a sun for a day miqaat, a moon for a night one, and both when the date has both. Hover a marked day to see the titles. Marker colour follows the highest priority on that day — gold major, teal notable, grey minor. By default only priority 1 and 2 occasions are shown — minor (priority 3) ones are opt-in via data-miqaat-priority="3".

How to drop into your project

1. Include the two files

<link rel="stylesheet" href="src/hijri-calendar/hijri-calendar-plugin.css">
<script src="hijri-calendar-plugin.js"></script>

2. Mark any input you want to bind

<input type="text" name="dob" data-hijri-picker>
<!-- default mode = "gregorian". Force Hijri default: -->
<input type="text" name="hijri_dob" data-hijri-picker data-hijri-mode="hijri">

3. Or attach manually from JS

HijriCalendar.attach(document.getElementById('myInput'), {
  defaultMode: 'hijri',
  onChange: function (val) {
    console.log(val.gregorian); // "2026-05-06"
    console.log(val.hijri);     // { hy: 1447, hm: 11, hd: 19 }
  }
});

Restricting / greying out dates

Every restriction works both as an HTML attribute and as a JS option. Blocked dates render with a hatched grey background, a strike-through number, and are not clickable. All values are Gregorian YYYY-MM-DD.

A) Pure HTML — data attributes

<!-- Only allow a date range (min..max inclusive) -->
<input type="text" name="visit" data-hijri-picker
       data-min-date="2026-06-10"
       data-max-date="2026-07-05">

<!-- Block weekdays: 0=Sun 1=Mon 2=Tue 3=Wed 4=Thu 5=Fri 6=Sat -->
<input type="text" name="appt" data-hijri-picker
       data-disabled-weekdays="0,5">   <!-- no Sundays or Fridays -->

<!-- Block a specific list of dates (comma separated) -->
<input type="text" name="slot" data-hijri-picker
       data-disabled-dates="2026-06-15,2026-06-18,2026-06-25">

B) JavaScript — options

HijriCalendar.attach(input, {
  minDate: '2026-06-01',                 // earliest selectable
  maxDate: '2026-12-31',                 // latest selectable
  disabledWeekdays: [0, 6],              // block Sun + Sat
  disabledDates: ['2026-07-04', '2026-08-14'],

  // Custom rule — return true to BLOCK the date.
  // Receives both calendars so you can gate on Hijri too.
  isDisabled: function (d) {
    // d = { gy, gm, gd, gregorian, weekday, hijri:{hy,hm,hd} }
    if (d.hijri.hm === 9) return true;   // block all of Ramadan
    return false;
  }
});

How isDisabled works

The plugin calls isDisabled(d) once for every day-cell it renders. The argument d has these fields: 

d = {
  gy: 2026, gm: 6, gd: 15,         // Gregorian year / month / day
  gregorian: '2026-06-15',          // ISO string, ready to compare
  weekday: 1,                       // 0=Sun 1=Mon ... 6=Sat
  hijri: { hy: 1447, hm: 12, hd: 20 } // Hijri equivalent
}

Return true to make the cell greyed-out & non-clickable. It runs on top of minDate, maxDate, disabledWeekdays, and disabledDates — all four are checked independently and any one blocking is enough to disable the cell. 

// Block every day during Ramadaan al-Moazzam across all years:
isDisabled: function (d) { return d.hijri.hm === 9; }

// Block even Gregorian days:
isDisabled: function (d) { return d.gd % 2 === 0; }

// Block everything in July:
isDisabled: function (d) { return d.gm === 7; }

// Block a whole Hijri year:
isDisabled: function (d) { return d.hijri.hy === 1448; }

// Allow ONLY the next 14 days from today:
isDisabled: function (d) {
  var today = new Date();
  var t = new Date(d.gy, d.gm - 1, d.gd);
  var diffDays = (t - today) / 86400000;
  return diffDays < 0 || diffDays > 14;
}

C) Change restrictions at runtime with setConstraints

picker.setConstraints({...}) accepts the same keys as the original options. Only the keys you pass are updated — others remain unchanged. The calendar re-renders immediately if it is currently open. 

var picker = HijriCalendar.attach(input);

// Narrow the allowed window at any time:
picker.setConstraints({ minDate: '2026-06-20', maxDate: '2026-06-30' });

// Add a custom rule after the fact:
picker.setConstraints({
  isDisabled: function (d) { return d.weekday === 5; } // block Fridays
});

// Remove minDate (pass null to clear it):
picker.setConstraints({ minDate: null });

// Common pattern — never allow past dates:
var t = new Date();
var iso = t.getFullYear() + '-' +
  String(t.getMonth()+1).padStart(2,'0') + '-' +
  String(t.getDate()).padStart(2,'0');
picker.setConstraints({ minDate: iso });

D) Two fields as a range (from / to)

var from = HijriCalendar.attach(fromInput, {
  onChange: function (v) {
    // lock the "to" field so it can't be before "from"
    to.setConstraints({ minDate: v.gregorian });
  }
});
var to = HijriCalendar.attach(toInput);

Submitting Gregorian under the input's own name

By default your server reads the Gregorian date from <name>_gregorian. If you are converting an existing application and don't want to touch every page's server-side code, turn on gregorianValue — the input's own name then carries YYYY-MM-DD, while the box still displays the Hijri (or Gregorian) date to the user. 

// ONE call flips the whole application. Put it right after the
// plugin script tag, before the pickers are attached:
<script src="hijri-calendar-plugin.js"></script>
<script>HijriCalendar.setDefaults({ gregorianValue: true });</script>

// or per input, in HTML:
<input type="text" name="dob" data-hijri-picker data-gregorian-value>

// or per input, in JS:
HijriCalendar.attach(input, { gregorianValue: true });

// ...and exempt a single legacy field that must keep receiving the
// display string, even though the app is flipped on globally:
<input type="text" name="legacy_dob" data-hijri-picker
       data-gregorian-value="false">

Precedence is always per-input JS option → per-input data-attribute → setDefaults(), so data-gregorian-value="false" (or "0") reliably opts one field out of a global switch-on. The same precedence applies to data-hijri-mode, data-min-date, data-max-date, data-disabled-weekdays and data-disabled-dates.

What each mode sends when the user picks 6 May 2026 in the Hijri view: 

// gregorianValue OFF (default)
dob           = "20 Zilqadah al-Haraam 1447 AH"
dob_gregorian = "2026-05-06"

// gregorianValue ON
dob           = "2026-05-06"      <-- existing server code just works
dob_gregorian = "2026-05-06"      <-- still sent, for compatibility

Mechanically, the plugin moves the name off the visible input onto a hidden field (a form submits an input's value, and here the displayed value must differ from the submitted one). The visible input keeps its id, so <label for="…"> and any JS that targets it by id are unaffected. Read the display text with input.value and the original name from input.dataset.hcpName.

What the backend receives

Next to every bound input, the plugin inserts a hidden field named <name>_gregorian holding the canonical Gregorian date as YYYY-MM-DD — regardless of which calendar the user actually picked from. 

// User picked 20 Zilqadah al-Haraam 1447 in the Hijri view.
// Form payload:
//   dob           = "20 Zilqadah al-Haraam 1447 AH"  // display only
//   dob_gregorian = "2026-05-06"                     // store this

Customise month names

Override the names globally (affects every picker) or per-instance. Pass 12 strings in calendar order — Moharram al-Haraam → Zilhaj al-Haraam for Hijri, January → December for Gregorian. 

// Global — e.g. switch Hijri labels to Arabic script
HijriCalendar.setHijriMonths([
  '\u0645\u062d\u0631\u0651\u0645','\u0635\u0641\u0631','\u0631\u0628\u064a\u0639 \u0627\u0644\u0623\u0648\u0644','\u0631\u0628\u064a\u0639 \u0627\u0644\u062b\u0627\u0646\u064a',
  '\u062c\u0645\u0627\u062f\u0649 \u0627\u0644\u0623\u0648\u0644\u0649','\u062c\u0645\u0627\u062f\u0649 \u0627\u0644\u0622\u062e\u0631\u0629','\u0631\u062c\u0628','\u0634\u0639\u0628\u0627\u0646',
  '\u0631\u0645\u0636\u0627\u0646','\u0634\u0648\u0651\u0627\u0644','\u0630\u0648 \u0627\u0644\u0642\u0639\u062f\u0629','\u0630\u0648 \u0627\u0644\u062d\u062c\u0651\u0629'
]);

// Or per-instance — only for this one input
HijriCalendar.attach(myInput, {
  hijriMonths: ['Muh','Saf','Rab1','Rab2','Jum1','Jum2','Raj','Sha','Ram','Shw','Qad','Hij']
});

Miqaat markers

Miqaat support is an optional third file. Without it the picker behaves exactly as before and shows no markers. 

<link rel="stylesheet" href="src/hijri-calendar/hijri-calendar-plugin.css">
<script src="hijri-calendar-plugin.js"></script>
<!-- optional: adds the occasion markers -->
<script src="hijri-calendar-miqaats.js"></script>

A day with a day miqaat gets a sun, a night miqaat gets a moon, and a date with both gets both. Hover (or keyboard-focus) a marked day for the titles and descriptions; the same text is set as the cell's aria-label for screen readers and touch.

Hiding the markers

<!-- one field -->
<input type="text" name="dob" data-hijri-picker data-show-miqaats="false">

// one picker, in JS
HijriCalendar.attach(input, { showMiqaats: false });

// everywhere
HijriCalendar.setDefaults({ showMiqaats: false });

// at runtime
var p = HijriCalendar.attach(input);
p.setShowMiqaats(false);   // and true to bring them back

// or drop the data entirely (hides them on every picker)
HijriCalendar.setMiqaats(null);

Reading miqaats yourself

// by Hijri date
HijriCalendar.getMiqaats(1448, 1, 10);
// -> [ { title: 'Yawme Ashura', description: null,
//        phase: 'day', priority: 1, year: null, month: 1, date: 10 }, ... ]

// by Gregorian date
HijriCalendar.getMiqaatsForGregorian(2026, 7, 30);

// is any data loaded?
HijriCalendar.hasMiqaatData();   // true once the add-on file is included

// show them alongside the picked date
HijriCalendar.attach(input, {
  onChange: function (v) {
    var list = HijriCalendar.getMiqaats(v.hijri.hy, v.hijri.hm, v.hijri.hd);
    console.log(list.map(function (m) { return m.title; }));
  }
});

Supplying your own occasions

// replace the data outright
HijriCalendar.setMiqaats([
  { month: 1, date: 10, phase: 'day',   priority: 1,
    year: null, title: 'Yawme Ashura', description: null }
]);

// or add your own on top of the bundled set
HijriCalendar.addMiqaats([
  { month: 6, date: 12, phase: 'night', priority: 2,
    year: 1449, title: 'Our anniversary', description: 'Office closed' }
]);

Fields: month/date are 1-based Hijri (1 = Moharram al-Haraam); phase is 'day' or 'night' and picks the sun or moon; priority 1/2/3 sets the marker colour; and year is null for every year or a Hijri year the occasion starts from (that is how the bundled data marks the 52nd Dai's urus as beginning in 1435).

Public API

HijriCalendar.attach(input, options)
HijriCalendar.attachAll(selector)            // default '[data-hijri-picker]'
HijriCalendar.toHijri(gy, gm, gd)            // -> { hy, hm, hd }
HijriCalendar.toGregorian(hy, hm, hd)        // -> { gy, gm, gd }
HijriCalendar.setDefaults({ ... })           // global option defaults
HijriCalendar.getDefaults()                  // read them back
HijriCalendar.setHijriMonths(names12)        // override global Hijri names
HijriCalendar.setGregorianMonths(names12)    // override global Greg names

// month names + calendar helpers (month numbers are 1-based,
// unlike the upstream repo which uses 0-based months):
HijriCalendar.HIJRI_MONTHS                   // string[12] long names
HijriCalendar.HIJRI_MONTHS_SHORT             // string[12] short names
HijriCalendar.getMonthName(hm)               // 9  -> 'Ramadaan al-Moazzam'
HijriCalendar.getShortMonthName(hm)          // 9  -> 'Ramadaan'
HijriCalendar.isKabisa(hy)                   // 1439 -> true (leap year)
HijriCalendar.hijriMonthLength(hy, hm)       // days in that Hijri month

// miqaats (needs hijri-calendar-miqaats.js)
HijriCalendar.setMiqaats(list|null)          // replace all data
HijriCalendar.addMiqaats(list)               // append entries
HijriCalendar.getMiqaats(hy, hm, hd)         // -> array, priority 1-2 only
HijriCalendar.getMiqaats(hy, hm, hd, 3)      // include minor occasions
HijriCalendar.getMiqaats(hy, hm, hd, null)   // no priority cap
HijriCalendar.getMiqaatsForGregorian(gy,gm,gd[, maxPriority])
HijriCalendar.hasMiqaatData()                // -> boolean
picker.setShowMiqaats(bool)                  // per-picker runtime toggle
picker.setMiqaatPriority(3|'all')            // per-picker priority cap

// instance methods (returned by attach()):
picker.getDate()                             // -> null | { gregorian:'YYYY-MM-DD',
                                             //      gy, gm, gd, hijri:{hy,hm,hd}, date:Date }
picker.setDate('2026-05-06')                 // ISO string
picker.setDate(new Date())                   // Date
picker.setDate({ hy:1447, hm:11, hd:20 })    // Hijri parts
picker.setDate(null)                         // clear (same as picker.clear())
picker.setDate(v, { notify: true })          // also fire onChange / hcp:change
                                             // (default: silent, so linked
                                             //  pickers don't loop)
HijriCalendar.parseDate(v)                   // -> {gy,gm,gd} | null
// 'hcp:change' bubbles from the input on every user pick / clear,
// with the getDate() payload in event.detail.
picker.setConstraints({ minDate, maxDate, disabledWeekdays,
                        disabledDates, isDisabled })

// options for attach():
//   showMiqaats:      false -> hide the sun/moon occasion markers
//   miqaatPriority:   2 (default) | 1 | 3 | 'all'
//                     highest priority number shown; 3 adds minor miqaats
//   gregorianValue:   true -> input's own name submits YYYY-MM-DD
//   defaultMode:      'hijri' | 'gregorian'
//   hijriMonths:      string[12]   // per-instance month-name override
//   gregMonths:       string[12]
//   minDate / maxDate:'YYYY-MM-DD' // selectable range (inclusive)
//   disabledWeekdays: number[]     // 0=Sun .. 6=Sat
//   disabledDates:    string[]     // ['YYYY-MM-DD', ...]
//   isDisabled:       fn(d)->bool // d={gy,gm,gd,gregorian,weekday,hijri}
//   onChange:         fn({ gregorian, hijri })

// HTML data-attributes (mirror the options):
//   data-hijri-picker  data-hijri-mode="hijri"
//   data-min-date  data-max-date
//   data-disabled-weekdays="0,5"
//   data-disabled-dates="2026-06-15,2026-06-18"
//   data-show-miqaats="false"  data-gregorian-value="false"
//   data-miqaat-priority="3"   // show minor occasions too (default 2)

Credits

The calendar math and the miqaat data in this plugin are not original work. Both were taken from mumineen_calendar_js by Murtaza Gulamali (@mygulamali), whose implementation and help made this possible.

  • The Misri-Hijri (Fatimid / Isma'ili / Tayyibi / Dawoodi Bohra) conversion formulas, the 30-year kabisa cycle (2, 5, 8, 10, 13, 16, 19, 21, 24, 27, 29) and the Julian-Day epoch come from his hijri_date.js.
  • The Hijri month names are used verbatim from his MONTH_NAMES.
  • The bundled miqaat list is transcribed from his source/data/miqaats.json.

This plugin adds the picker UI, the dual-calendar toggle, date restrictions and the ASP.NET validation handling on top of that groundwork. Conversions were diffed against his implementation across every day from 1900–2100 to confirm they agree. Please credit him in any further reuse.
